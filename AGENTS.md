# AGENTS.md — OpenGLApp511

## Обзор проекта

OpenGLApp511 — учебное графическое приложение на C# / .NET 9, использующее OpenGL через библиотеку OpenTK. Это порт примера «program 5.1» из учебника по компьютерной графике (оригинал на C++ / GLFW / GLEW): полноэкранное окно с вращающейся текстурированной пирамидой. Повороты выполняются клавишами клавиатуры.

Комментарии в коде и документация ведутся на русском языке — новые комментарии тоже следует писать по-русски. Комментарии в коде часто ссылаются на соответствующие функции/приёмы из C++-оригинала (`init`, `display`, `setupVertices`, `key_callback`); эту связь с оригиналом важно сохранять.

## Технологический стек

- **Язык / платформа:** C#, .NET 9 (`net9.0`), `ImplicitUsings` и `Nullable` включены.
- **OpenGL-обвязка:** OpenTK 4.8.2 (`OpenTK`, `OpenTK.Graphics`). Контекст OpenGL 4.3 Core, ForwardCompatible.
- **Загрузка текстур:** StbImageSharp 2.30.15.
- **IDE:** Visual Studio 2022 (решение `OpenGLApp511.sln`, конфигурации Debug|Any CPU / Release|Any CPU).
- **Шейдеры:** GLSL 4.30, лежат в `shaders/`.
- **Текстуры:** PNG в `textures/` (сейчас — `brick.png`).

## Структура кода

Проект маленький, всего два исходных файла в корне, общее пространство имён `OpenGLApp511`:

- `Program.cs`
  - `class Game : GameWindow` — вся сцена: вершинные данные пирамиды (18 вершин, 6 треугольников) и текстурные координаты зашиты массивами прямо в класс; 1 VAO + 2 VBO.
    - `OnLoad()` — аналог `init()`: компиляция шейдерной программы, загрузка текстуры, заполнение буферов (`SetupVertices()`), установка perspective-матрицы (FOV 60°, near 0.1, far 50).
    - `OnRenderFrame()` — аналог `display()`: построение model/view-матриц, передача uniform'ов `proj_matrix` и `mv_matrix`, отрисовка `GL.DrawArrays(Triangles, 0, 18)`.
    - `OnUpdateFrame()` — обработка клавиатуры. В отличие от C++-оригинала (события `GLFW_PRESS/REPEAT`) используется опрос `KeyboardState.IsKeyDown` каждый кадр — это сделано намеренно для плавности вращения.
  - `static class Program` — точка входа `Main()`: окно 1920×1080, Fullscreen, заголовок ` program_5_1_1 `.
- `Utils.cs` — статический класс-хелпер (порт `Utils` из C++-примера):
  - `CreateShaderProgram(vertPath, fragPath)` — компиляция и линковка шейдеров, ошибки печатаются в консоль.
  - `CheckOpenGLError()` — опрос `GL.GetError()`.
  - `LoadTexture(path)` — загрузка через StbImageSharp (с вертикальным переворотом), фильтрация Linear, wrap Repeat, генерация mipmaps.

## Сборка и запуск

```bash
dotnet restore
dotnet build
dotnet run          # полноэкранное окно; выход — клавиша Esc
```

Альтернатива — открыть `OpenGLApp511.sln` в Visual Studio и собрать/запустить оттуда (F5).

Шейдеры (`shaders/**/*`) и текстуры (`textures/**/*`) подключены в `.csproj` как `Content` с `CopyToOutputDirectory=PreserveNewest` — при сборке они копируются в каталог вывода, а в коде открываются по относительным путям (`./shaders/...`, `textures/...`). Поэтому запускать exe нужно из каталога сборки (или через `dotnet run` из корня). Для запуска требуется GPU/драйвер с поддержкой OpenGL 4.3 Core.

## Управление

- `W` / `S` — вращение вокруг оси X
- `A` / `D` — вращение вокруг оси Y
- `Q` / `E` — вращение вокруг оси Z
- `Esc` — выход

## Тестирование

Тестов в проекте нет (нет тестового проекта и тестовых фреймворков). Проверка изменений — успешная сборка (`dotnet build`, должно быть 0 предупреждений/ошибок) и визуальный запуск приложения.

## Соглашения по коду

- Стиль — стандартный современный C#: PascalCase для типов и методов, camelCase для приватных полей и локальных переменных, без префиксов, `var` по вкусу.
- Имена и структура намеренно повторяют C++-оригинал (`SetupVertices`, `renderingProgram`, `vao`/`vbo`, комментарии вида `---- display(...) ----`) — при изменениях сохранять это соответствие.
- Обработка ошибок — через вывод в `Console` (без исключений), как в оригинале.
- Новые шейдеры класть в `shaders/`, текстуры — в `textures/`; они подхватятся глобами в `.csproj` автоматически.

## Известные особенности

- В шейдерах sampler объявлен как `layout(binding=0) uniform sampler2D samp`, а `Program.cs` вызывает `GL.GetUniformLocation(renderingProgram, "brickTex")` и `GL.Uniform1(texLoc, 0)`. Такое имя uniform'а в шейдере отсутствует, поэтому вызов фактически ничего не делает; текстура работает благодаря явному `binding=0` в GLSL. Это наследие оригинального примера — при переименовании sampler'а учитывать обе стороны.
- Поле `tfLoc` объявлено, но не используется (как и в C++-оригинале).
- Деплоймент как таковой отсутствует: проект — локальная учебная программа, CI/CD и публикация не настроены.
